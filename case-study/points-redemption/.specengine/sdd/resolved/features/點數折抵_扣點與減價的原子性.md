# 釐清問題
折抵成功時要同時「扣除會員點數」與「減少訂單應付金額」。若其中一步失敗（例如資料庫寫入錯誤），另一步已完成的變更要怎麼處理？

# 定位
R-POINTS_REDEMPTION-000 的 post_assertions；members.points_balance 與 orders.payable_amount（模組 POINTS_REDEMPTION）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 同一交易（Transaction）內完成，任一步失敗全部回滾，對外呈現「折抵失敗」 |
| B | 先扣點再減價，減價失敗時補償性退點（Saga），並記錄補償結果 |
| C | 允許暫時不一致，由背景對帳程序修復 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
Driver／Service 的實作邊界；是否需要失敗注入的測試 Scenario；spec-05 的實作方式。

# 優先級
High
