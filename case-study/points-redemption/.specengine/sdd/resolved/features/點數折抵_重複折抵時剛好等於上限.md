# 釐清問題
流程對齊（spec-flow-align）時發現的缺口：R-POINTS_REDEMPTION-003 規定「首次折抵時，欲折抵點數剛好等於上限（訂單金額或餘額取較小者）可以折」，但在重複折抵以新換舊（R-POINTS_REDEMPTION-006）的情境下，新的折抵點數 N新 剛好等於「退回舊折抵後的會員點數餘額」、或剛好等於訂單金額時，矩陣沒有說能不能折。

# 定位
R-POINTS_REDEMPTION-003、R-POINTS_REDEMPTION-006（模組 POINTS_REDEMPTION）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 可以折：等於上限的規則在重複折抵時同樣適用，上限以「退回舊折抵後的餘額」與「訂單金額」取較小者；R-003 擴充前置條件涵蓋重複折抵情境 |
| B | 不可以折：重複折抵時 N新 必須嚴格小於上限（等於視為超過，依 R-001／R-002 拒絕）；新增一條獨立 Rule 描述此差異 |
| C | 可以折，但以「退回前的餘額」為上限而非退回後（等同不先退舊再檢查，與 R-006 既有敘述矛盾，需同時修改 R-006） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
R-003 的 pre_conditions（是否移除「訂單尚無生效中折抵」的隱含前提）；R-006 的上限檢查敘述；spec-03 中重複折抵 Scenario Outline 的邊界範例列；Driver「折抵」在重複折抵時的上限計算。
