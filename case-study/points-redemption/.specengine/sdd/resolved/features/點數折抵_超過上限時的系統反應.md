# 釐清問題
需求說折抵點數「不能超過訂單金額，也不能超過會員目前的點數餘額」，但沒說當會員輸入的點數超過上限時系統要怎麼反應。上限值本身已確定（訂單金額與點數餘額取較小者），這題只問超過時的行為。

# 定位
R-POINTS_REDEMPTION-001、R-POINTS_REDEMPTION-002（模組 POINTS_REDEMPTION）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕並回報錯誤：折抵不成立，餘額與應付金額不變，告知會員可折抵上限 |
| B | 自動截斷至上限並繼續折抵：以「訂單金額與點數餘額取較小者」成交，並提示已調整 |
| C | 忽略本次操作並顯示警告：不折抵、不報錯，只顯示 Warning |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
R-001／R-002 的 post_assertions 與對應 Scenario；Driver 介面「折抵」方法的回傳型別（成功／錯誤／調整後金額）；orders.redeemed_points 的寫入時機。

- **決策選項**：A — 拒絕並回報錯誤。使用者補充：超過餘額時訊息「折抵點數超過餘額」，超過訂單金額時「折抵點數超過訂單金額」，兩者皆超過以餘額為準
