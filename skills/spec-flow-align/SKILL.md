# 目標

逐題 MCQ 容易「見樹不見林」。本階段把矩陣所有 Rule 依子情境分組畫成流程圖，讓使用者用「看圖」做最後一次完整性確認。有缺口時不腦補，改用 MCQ 補問並把狀態退回 `CLARIFYING`；但使用者在確認過程中裁示的「這不是缺口」與「這幾張圖沒問題」要立刻存下來，下次重畫不重問。

---

# 硬性約束

1. **只畫既有 Rule**：流程圖 100% 依據矩陣，嚴禁加入矩陣中不存在的分支。自己發現的疑似缺口列在「執行者疑似缺口」區請使用者裁示，不直接補畫。
2. **真實等待確認**：印出後【必須真實等待使用者輸入】。被 `spec-run` 委派呼叫時亦同。
3. **缺口走 MCQ**：依 `${CLAUDE_PLUGIN_ROOT}/skills/spec-01-discovery-bootstrap/references/mcq-file-format.md` 建檔，「來源」填 `spec-flow-align`。
4. **裁示必落盤**：不論本輪通過與否，使用者裁示的「非缺口」與「已確認無不一致的圖」都寫進索引檔（格式見 contract-rules 第 5.5 節）。
5. **命名空間**：只讀寫本模組的 `matrix/`、`overview/`、`flow-design/<MODULE_ID>.md` 與 `flow-design/<MODULE_ID>/`。

---

# 執行步驟

## Step 0: 模組解析與前置檢查

1. 比照 spec-02 Step 0 鎖定 `MODULE_ID`。
2. `node "${CLAUDE_PLUGIN_ROOT}/scripts/spec-status.js" --module <MODULE_ID> --json`：`pending` 須為 0，否則拒絕執行並提示先完成 `spec 02`。`flowAligned` 已為 true → 回報「已通過流程對齊」後結束。
3. 若 `flow-design/<MODULE_ID>.md` 存在但狀態為「未通過」，讀出其中「使用者已裁示非缺口」與「已確認無不一致的流程圖」，本輪沿用。

## Step 1: 讀取矩陣與刻意不做清單、分組

1. 讀矩陣全部 Rule，萃取「起點狀態 → 動作 → 分支條件 → 結果狀態」。讀 `exclusions.md` 中屬於本模組的條目。
2. 依業務邏輯自然分組，每組命名繁體中文「流程階段名稱」。同一 Rule 可出現在多張圖（在後者註明「沿用」）。
3. 每個節點標註 `rule_id`。

## Step 2: 產出流程圖並請求確認

每組一張 Mermaid `flowchart`，標籤全繁體中文。圖之外用白話逐條複述所有 Rule 並標 `rule_id`。

```text
====================================================================
🗺️ [模組：<MODULE_ID>] 流程圖對齊確認（第 N 次）
====================================================================

**圖 1：<流程階段名稱>（rule_id：...）**
```mermaid
<流程圖>
```
（依序列出各圖；上次已確認無不一致的圖標註「上次已確認」）

白話複述：
  1. <Rule 描述>（R-XXX-001）
  ...

已知取捨（exclusions.md 本模組條目 ＋ 使用者先前裁示）：
  - <內容>（X-XXX-001）

執行者疑似缺口（矩陣與 exclusions 都沒有、但我認為可能需要的，請裁示是缺口還是範圍外）：
  (a) <描述>
--------------------------------------------------------------------
請確認：
  (1) 有沒有遺漏的分支、使用者行為或畫面狀態？（含上列疑似缺口的裁示）
  (2) 圖上有沒有跟你原本設想不一致的地方？
沒問題請回覆「確認」；有缺口請直接描述。
====================================================================
```

【真實等待使用者輸入】。

## Step 3: 分歧處理

- **確認無缺口**：疑似缺口被裁示為「範圍外」或「非缺口」的，寫入 `exclusions.md`（類型「範圍外」）或索引的「已裁示非缺口」；進入 Step 4。
- **指出缺口**（含疑似缺口被裁示為缺口）：
  1. 每個缺口建 MCQ 檔至 `data/` 或 `features/`。
  2. 寫入或更新 `flow-design/<MODULE_ID>.md`：狀態行「狀態：未通過（缺口 N）」，加上本輪「使用者已裁示非缺口」與「已確認無不一致的流程圖」。
  3. `overview.md` 與 `overview/<MODULE_ID>.md` 狀態退回 `CLARIFYING`，更新待答數。
  4. 中止本輪，彙報列出新增問題。

## Step 4: 落盤（通過時）

1. 每個流程階段一份 `flow-design/<MODULE_ID>/<流程階段名稱>.md`：標題與摘要、`rule_id` 清單、Mermaid 圖、白話複述、已知取捨、確認時間。
2. 寫入 `flow-design/<MODULE_ID>.md`，第一行「狀態：已通過 ｜ 確認時間 ｜ Rule 總數」，含「使用者已裁示非缺口」「已確認無不一致的流程圖」「流程階段檔案」三區。
3. 狀態欄維持 `CLARIFIED`。

# 完成條件

- [ ] `pending` 為 0，`flowAligned` 原為 false
- [ ] 已沿用上次索引中的裁示（若有）
- [ ] 已分組、繪圖、白話複述、列出已知取捨與疑似缺口，真實等待
- [ ] 有缺口：MCQ 已建、索引已寫「未通過」並保存裁示、狀態已退回、本輪中止
- [ ] 無缺口：各流程階段檔案與「已通過」索引已落盤，裁示已寫入 exclusions 或索引
