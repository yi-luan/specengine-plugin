# MCQ 問題檔案格式規範

## 選項品質規範

- 選項必須代表具體的架構/業務抉擇（例如：`A. 拋出 400 錯誤阻斷` vs `B. 自動修飾數值至上限並繼續` vs `C. 忽略該操作並顯示 Warning`）。
- 保留 `Short` 選項供使用者自訂極簡回答 (<=5 字)。

## 可複用慣例候選判定 (Reusable Policy Candidate)

判斷此問題本質上是「跨模組通用的工程議題」（如精度捨去、軟刪除、冪等性策略）還是「僅屬本模組的業務特有邏輯」。前者標記 `Yes`，後者標記 `No`。

## 統一問題檔案格式

```markdown
# 釐清問題
<完整問題說明>

# 定位
<指向具體的 Entity.Attribute 或 Rule ID，並註明所屬模組 MODULE_ID>

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | <選項 A 描述> |
| B | <選項 B 描述> |
| C | <選項 C 描述> (選用) |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
<說明此決策影響哪些實體、API 或測試案例>

# 優先級
<High / Medium / Low>

# 可複用慣例候選 (Reusable Policy Candidate)
<Yes / No>
```
