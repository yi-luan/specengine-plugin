# 標準答案表（T5 限量搶購）— 回答者只准依此表回答

H 為必問的業務洞，隱藏測試有對應題目。N 為非功能需求的洞，用來觀察流程會不會主動問；N3、N4、N5 有對應的隱藏測試，N1、N2 只記錄有沒有被問到。

| 洞 | 類型 | 問題 | 標準答案 |
| :-- | :-- | :-- | :-- |
| H1 | 必問 | 剩餘不夠時怎麼辦？剛好等於可以嗎？能部分保留嗎？ | 剛好等於可以搶到。不夠就整筆拒絕，回 `SOLD_OUT`，不部分保留 |
| H2 | 必問 | 限購怎麼算？未付款的保留、已到期釋放的算不算？ | 保留中與已成交都算；已到期釋放的不算（釋放後可以再搶）。超過就整筆拒絕，回 `LIMIT_EXCEEDED` |
| H3 | 必問 | 開始／結束時刻的邊界？還沒開始、已經結束時回什麼？ | 開始時刻（含）起可搶，結束時刻（含）起不可搶。開始前回 `NOT_STARTED`，結束後回 `ENDED` |
| H4 | 必問 | 付款通知在保留到期後才到（但排程還沒釋放）？ | 以付款當下時間判斷：到期時刻（含）之後一律拒絕，回 `HOLD_EXPIRED`，即使排程還沒釋放；這張保留之後由排程照常釋放 |
| H5 | 必問 | 排程怎麼判定到期？剛好 10 分鐘算不算？ | 現在時間 ≥ 到期時間就釋放（剛好 10 分鐘算到期）。釋放後狀態為 `EXPIRED`，件數加回剩餘 |
| H6 | 必問 | 重複的付款通知？已釋放的保留收到付款？找不到的保留？ | 已成交的保留再收到通知：回成功、不改任何東西。已釋放的回 `HOLD_EXPIRED`。找不到回 `HOLD_NOT_FOUND` |
| H7 | 必問 | 搶購結束之後、保留還沒到期，還能付款嗎？ | 可以。搶購結束只影響搶，不影響付款 |
| H8 | 必問 | 同一個請求（同 requestId）重送？ | 前一次成功：回同一張保留（同 holdId、同到期時間），不重複佔名額、不重算限購。前一次失敗：當成新請求重新判斷 |
| H9 | 必問 | 輸入不合法？搶購不存在？重複開同一檔？ | 搶購：qty 不是正整數，或 saleId／customerId／requestId 為空字串 → `INVALID_INPUT`；搶購編號不存在 → `SALE_NOT_FOUND`。開搶購：quantity 或 perCustomerLimit 不是正整數、saleId 為空、開始時間不早於結束時間 → `INVALID_INPUT`；saleId 已存在 → `DUPLICATE_SALE`。都不改任何資料 |
| N1 | 非功能（只記錄） | 尖峰流量多大？幾台伺服器？ | 開賣第一秒約 2 萬次請求，3 台伺服器 |
| N2 | 非功能（只記錄） | 回應時間要求？ | 搶購請求 P99 在 300 毫秒內 |
| N3 | 非功能 | 很多人同時搶、系統很忙時，可以先回「請稍後再試」嗎？ | 不行。只要還有名額，同時送來的請求都要正常處理完（搶到或 `SOLD_OUT`），不能因為同時搶而失敗 |
| N4 | 非功能 | 一台伺服器當機，其他伺服器的請求最多可以被卡多久？ | 最多 5 秒。5 秒後其他伺服器必須能正常搶購 |
| N5 | 非功能 | 共用儲存連不上時怎麼辦？ | 回 `{ ok: false, reason: 'TRY_AGAIN' }`，不可丟出例外，不可讓顧客以為搶到 |
| N6 | 非功能（只記錄） | 商品頁的剩餘件數可以延遲嗎？可以快取嗎？ | 不行，要即時：任何一台伺服器搶到或釋放後，所有伺服器馬上看到新數字 |
| T-a | 陷阱 | （需求有寫）保留 10 分鐘 | 不該問保留多久 |
| T-b | 陷阱 | （需求有寫）付款通知可能重複、請求可能重送、伺服器可能當機或卡住 | 不該問「會不會」，該問「發生時怎麼辦」 |
| T-c | 陷阱 | （需求有寫）排程每台伺服器都跑 | 不該問排程跑在哪 |

回答規則：
- 問到表上的洞，照標準答案回答，不加油添醋。
- 問到表上沒有的業務或非功能問題，一律回答「你決定，照你的最佳判斷」並記錄該題。技術環境問題照專案實況回答。
- 不主動提示、不糾正、不要求補測試。
- 同時記錄每個 N 洞是在哪個階段被問到（spec-01 掃描、spec-02 釐清、flow-align、Spec Kit clarify 等），或從沒被問到。
