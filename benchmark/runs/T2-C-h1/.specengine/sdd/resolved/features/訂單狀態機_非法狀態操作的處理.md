# 釐清問題
需求未說明：訂單在不允許的狀態下呼叫操作時，系統要怎麼處理。

# 定位
ORDER_STATE_MACHINE 模組的 pay、ship、cancel、refund 四個操作在非法狀態下的行為

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕操作：回傳 ok 為 false 與失敗原因，傳入的訂單不被修改 |
| B | 忽略操作：回傳 ok 為 true 與原訂單，不報錯 |
| C | 拋出例外中斷呼叫，由呼叫方處理 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
四個狀態操作的失敗分支、失敗原因代碼、測試的非法狀態矩陣。

# 優先級
High

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 來源
spec-01

# 最終決策
- **決策選項**：A。拒絕，訂單不變。已出貨不可取消、已取消後任何操作、已付款未出貨直接退款、已退款後任何操作、已建立直接出貨，reason 固定為 `INVALID_TRANSITION`。
