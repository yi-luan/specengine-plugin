# 釐清問題
需求寫「金額皆為整數元」，但沒有說明傳入非整數金額時的行為；也沒有說明訂單編號 id 的格式要求。

# 定位
ORDER_STATE_MACHINE 模組的 createOrder(id, amount) 與 pay、refund 的 amount 參數驗證

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 非整數金額一律拒絕；id 不做格式檢查，由呼叫方負責唯一性 |
| B | 非整數金額一律拒絕；id 為空字串時也拒絕，唯一性由呼叫方負責 |
| C | 非整數金額直接無條件進位或捨去，id 不做檢查 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
createOrder 的參數驗證、pay 與 refund 的金額驗證，以及測試資料的邊界值。

# 優先級
Low

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：需求方授權由 Agent 判斷。決定：非整數與非正數金額一律拒絕，代碼 `INVALID_AMOUNT`；id 不做格式與唯一性檢查，唯一性由呼叫方負責，不新增錯誤代碼。
