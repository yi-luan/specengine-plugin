# 釐清問題
若優惠券的有效迄日（`valid_to`）早於有效起日（`valid_from`），或兩者格式不是合法的 ISO 8601 時間，系統應如何處理？需求未說明此種設定錯誤的行為。

# 定位
模組 COUPON｜Entity `coupons.valid_from` / `coupons.valid_to`

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 套用時一律判定為失敗（回傳失敗原因），不因設定錯誤而拋出例外 |
| B | 套用時拋出例外，由呼叫端處理 |
| C | 不驗證，依比較結果判定，迄日早於起日時等同永遠不可用 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
`applyCoupons` 的輸入驗證、失敗原因的回傳格式、測試的負向案例。

# 最終決策
- **決策選項**：迄日早於起日，或時間格式不合法，整筆拒絕，reason 為 `INVALID_COUPON`。需求方授權由 spec 代為判斷（回覆 13），採此選項因與券值不合法同屬「券設定本身錯誤」
