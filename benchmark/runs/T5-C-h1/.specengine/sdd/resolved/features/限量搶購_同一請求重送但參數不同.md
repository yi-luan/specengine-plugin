# 釐清問題
同一個 requestId 再次送來，若顧客、搶購編號或件數與第一次不同，系統應如何處理？

# 定位
FLASH_SALE 模組，R-FLASH_SALE-008（請求重送）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕，回傳請求編號衝突，不建立任何保留 |
| B | 視為新請求處理 |
| C | 忽略新參數，回傳第一次的結果 |

# 影響範圍
R-FLASH_SALE-008 的去重判斷與 grab_request 紀錄一致性。

# 優先級
Medium

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 來源
spec-01

# 最終決策
- **決策選項**：A（spec-02 依最佳判斷裁示，需求方授權）。同一 requestId 但參數不同 → 回傳 REQUEST_CONFLICT，不建立保留。理由：C 會讓呼叫端在參數被忽略時無從察覺，B 會讓去重失效。此條為 spec-02 的判斷，請於 flow-align 一併確認。
