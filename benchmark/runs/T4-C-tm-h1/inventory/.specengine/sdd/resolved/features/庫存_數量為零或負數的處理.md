# 釐清問題
需求第 9 點只說數量是整數，沒有說數量為 0 或負數時怎麼辦。`OrderPlaced` 帶來的數量為 0 或負數時，庫存服務應如何處理？

# 定位
INVENTORY 模組，Rule R-INVENTORY-000、R-INVENTORY-001（trigger: OrderPlaced）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 視為庫存不足，發出 `StockRejected` |
| B | 視為保留成功，不動庫存，發出 `StockReserved` |
| C | 拋出錯誤並停止處理，不發出事件 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
影響 R-INVENTORY-000、R-INVENTORY-001 的前置條件邊界；影響測試中零值與負值案例的期望結果。

# 最終決策
- **決策選項**：需求方回覆「2」並附「你決定，照你的最佳判斷」。授權由規格代決，代決結果為 A（視為庫存不足，發出 `StockRejected`，不保留）。理由：數量需為正整數（需求第 9 點），不合法的數量不應造成保留，且拒絕可讓訂單服務得到明確回應。
