# 釐清問題
同一張訂單的 `PaymentFailed` 或 `OrderCancelled` 重複抵達，或該訂單沒有保留中的庫存（已放回過，或從未保留成功）時，庫存服務應如何處理？

# 定位
INVENTORY 模組，Rule R-INVENTORY-002（trigger: PaymentFailed）、R-INVENTORY-003（trigger: OrderCancelled）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 不動庫存，也不發出任何事件；只有第一次真正放回時才發出 `StockReleased` |
| B | 不動庫存，但仍發出 `StockReleased` |
| C | 拋出錯誤並記錄，不發出事件 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
影響 R-INVENTORY-002、R-INVENTORY-003 的前置條件與 post_assertions；影響 `StockReleased` 是否可能重複發出。

# 最終決策
- **決策選項**：需求方回覆「7A」，並補充：「只放回實際保留的數量，同一張訂單最多放回一次；沒保留過就不加庫存、不發 `StockReleased`。」
- **寫回位置**：矩陣 R-INVENTORY-002、R-INVENTORY-003（放回實際保留數量、一次性）、R-INVENTORY-008（無保留時不加庫存、不發事件）
