# 釐清問題
Q5 的答案只規定「取消」先於下單抵達時的行為。同樣的亂序情況若是「付款失敗」先於下單抵達（此時庫存服務沒有該訂單的保留紀錄），庫存服務應如何處理？

# 定位
INVENTORY 模組，Rule R-INVENTORY-002（trigger: PaymentFailed）、R-INVENTORY-000（trigger: OrderPlaced）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 記住該訂單已付款失敗（與取消先到的處理一致）；之後到的 OrderPlaced 不保留庫存、不發任何事件 |
| B | 付款失敗先到時不做任何記錄、不動庫存；之後到的 OrderPlaced 照常保留，庫存會一直被佔用 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
影響 R-INVENTORY-002 的前置條件與 post_assertions，以及是否需要新增「付款失敗已記錄」的 Rule；影響付款失敗先到時 OrderPlaced 的結果。

# 優先級
High

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 來源
spec-02（Q5 答案後發現的新缺口）

# 最終決策
- **決策選項**：需求方回覆「這題你決定，照你的最佳判斷」。授權由規格代決，代決結果為 A。理由：B 會讓庫存被永久佔用（付款已失敗卻沒有人放回），與需求第 5 點「付款失敗時放回庫存」的精神衝突；A 與取消先到的處理一致。
- **寫回位置**：矩陣 R-INVENTORY-009（新增，付款失敗先到則記住、不動庫存、不發事件）、R-INVENTORY-007（已取消或付款失敗的訂單收到 OrderPlaced 不保留）
