# 釐清問題
需求第 8 點說事件不保證先後順序。若 `OrderCancelled` 或 `PaymentFailed` 比 `OrderPlaced` 先抵達（此時庫存服務尚無該訂單的保留紀錄），之後 `OrderPlaced` 才抵達，庫存服務應如何處理？

# 定位
INVENTORY 模組，Rule R-INVENTORY-002（trigger: PaymentFailed）、R-INVENTORY-003（trigger: OrderCancelled）、R-INVENTORY-000（trigger: OrderPlaced）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 先記下待放回；`OrderPlaced` 抵達時照常保留，並立即放回 |
| B | 先到的放回請求直接丟棄；之後 `OrderPlaced` 照常保留 |
| C | 拋出錯誤並停止處理，由外部重試 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
影響 R-INVENTORY-002、R-INVENTORY-003 的前置條件；影響是否需要持久化紀錄。

High

# 最終決策
- **決策選項**：需求方回覆「5 短」，自訂內容：「庫存服務記住這張訂單已取消；之後到的 `OrderPlaced` 不保留庫存、不發任何事件。」此答案只涵蓋「取消先到」。「付款失敗先到」的情況需求方未回答，已另開新題「庫存_付款失敗先於下單抵達」。
- **寫回位置**：矩陣 R-INVENTORY-006（取消先到，記住已取消）、R-INVENTORY-007（已取消的訂單收到 OrderPlaced，不保留、不發事件）
