# 釐清問題
R-PAYMENT-003 暫存的 StockReserved，如果該訂單的 OrderPlaced 永遠不到，暫存要怎麼清除？

# 定位
PAYMENT：R-PAYMENT-003（先到的庫存保留暫存）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 暫存不設時間上限，直到該訂單的 OrderPlaced 抵達（依 R-000／001 處理）或該訂單的 OrderCancelled 抵達（丟棄暫存）為止 |
| B | 暫存 15 分鐘，逾時丟棄（時間與訂單服務的逾時取消不同步，可能誤丟） |
| C | 不暫存，立即丟棄 StockReserved（事件至少送達一次時，會造成該訂單漏扣款） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
R-PAYMENT-003 的 post_assertions；R-PAYMENT-005 需新增丟棄暫存的動作；記憶體佔用會隨未完成訂單增長。

# 優先級
High

# 可複用慣例候選 (Reusable Policy Candidate)

- **決策選項**：由執行者決定（需求方回覆：「(a)、(b)：你決定，照你的最佳判斷。」）。選 A。理由：事件至少送達一次，OrderPlaced 最終一定會到，暫存才能保證不漏扣；B 的 15 分鐘與訂單服務計時不同步，會誤丟；C 會漏扣。代價是記憶體佔用，本模組為記憶體實作，接受此代價。
- **寫回位置**：矩陣 R-PAYMENT-003 post_assertions（不設時間上限）、R-PAYMENT-005 post_assertions（丟棄暫存）；resolved_by 指向本檔；policy-defaults.md POLICY-004 立場補註「不設時間上限，由依賴事件或取消事件清除」
