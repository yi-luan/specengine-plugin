# 釐清問題
事件傳遞不保證先後順序。付款服務有可能先收到 `StockReserved`，但還沒收到該訂單的 `OrderPlaced`。`StockReserved` 本身只帶訂單編號，沒有顧客與金額，付款服務不知道要向哪位顧客扣多少錢。

# 定位
PAYMENT：R-PAYMENT-000（主流程：收到 StockReserved 後扣款）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 暫存這筆 StockReserved，等該訂單的 OrderPlaced 抵達後再扣款（需要保存待處理清單） |
| B | 立即拒絕：發出 PaymentFailed |
| C | 忽略這筆事件，依賴事件至少送達一次的保證，等它重送後再處理 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
付款服務的記憶體狀態（待處理清單）、新增 R-PAYMENT-003、R-PAYMENT-000 的前置條件。
