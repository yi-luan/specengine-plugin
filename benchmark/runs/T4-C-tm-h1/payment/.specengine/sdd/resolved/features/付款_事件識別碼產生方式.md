# 釐清問題
需求要求「各服務自行產生事件 id，必須在全系統內唯一」。付款服務要發出 PaymentSucceeded、PaymentFailed、PaymentRefunded，這些事件的 id 要用哪種方式產生？

# 定位
PAYMENT：模組層級（事件識別碼的產生規則）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 前綴 `PAY-` 加上本服務的流水號 |
| B | 決定性 id：`PAY-<orderId>-<事件類型>` |
| C | 隨機 UUID |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
付款服務發出的所有事件 id 格式。

# 優先級
Medium

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：由執行者決定（需求方授權「你決定，照你的最佳判斷」）。選 B：`PAY-<orderId>-<事件類型>`。理由：同一業務事件重發時 id 相同，下游可靠 id 去重；本服務每筆訂單每類型最多發一次，id 不會衝突；前綴確保全系統唯一。
