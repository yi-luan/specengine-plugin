# 釐清問題
訂單金額本身不合理時要怎麼處理？例如負數、非整數。另外訂單金額為 0 元時算不算合理？

# 定位
TENANT_COUPON：checkout_orders.order_amount（ApplyInput.orderAmount）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 負數或非整數 → 整筆失敗，回報「訂單金額不合法」；0 元視為合法（照一般規則處理，折扣後仍為 0） |
| B | 負數、非整數、0 元都整筆失敗，回報「訂單金額不合法」 |
| C | 不檢查：視為呼叫端責任，本模組不保證結果，也不寫測試 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
erm.dbml order_amount 約束、輸入驗證分支與測試案例

# 優先級
Medium

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：B：orderAmount 為 0、負數或非整數時拒絕，reason 固定為 INVALID_INPUT
