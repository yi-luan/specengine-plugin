# 釐清問題
傳入的優惠券資料本身不合理時要怎麼處理？例如：百分比折扣的百分比 ≤ 0 或 > 100、固定金額折扣金額 ≤ 0、折扣值或最低消費不是整數、有效期間起點晚於迄點。

# 定位
TENANT_COUPON：Coupon.value、Coupon.minOrderAmount、Coupon.validFrom／validTo（coupons 表約束）

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 檢查並拒絕：任一張券資料不合理即整筆失敗，回報「優惠券資料不合法」原因（百分比合法範圍 1～100，固定金額 ≥ 1） |
| B | 不檢查：視為呼叫端責任，本模組不保證結果，也不寫測試 |
| C | 視同「不可用的券」，依「部分優惠券不可用時的處理」那題的決定處理 |
| Short | 自訂簡答 (<=5 字) |

# 最終決策
- **決策選項**：A（範圍限定）：券本身的值不合法（PERCENT 不在 1～100、FIXED ≤ 0、非整數）拒絕，reason 固定為 INVALID_COUPON。最低消費不是整數、有效期間起點晚於迄點兩項由需求方授權執行者裁量 → 執行者決定：兩者皆視為券資料不合法回報 INVALID_COUPON；起點等於迄點視為合法
