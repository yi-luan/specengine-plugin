# 折抵前置檢查

會員結帳使用點數折抵時，依固定順序做四道檢查，任一不過即整筆拒絕並回傳固定失敗原因；全部通過才進入「折抵成交與結果回傳」。

## rule_id
- R-POINTS_REDEMPTION-004（輸入非法 INVALID_INPUT）
- R-POINTS_REDEMPTION-001（點數格式非法 INVALID_POINTS）
- R-POINTS_REDEMPTION-003（點數不足 INSUFFICIENT_POINTS）
- R-POINTS_REDEMPTION-002（超過折抵上限 EXCEEDS_LIMIT）

## 流程圖
```mermaid
flowchart TD
  S([會員結帳時使用點數折抵現金]) --> C1{訂單金額 <= 0 或非整數<br/>或 點數餘額 < 0 或非整數？}
  C1 -- 是 --> F4[折抵不成功<br/>reason = INVALID_INPUT<br/>R-POINTS_REDEMPTION-004]
  C1 -- 否 --> C2{折抵點數非整數<br/>或 為負數？}
  C2 -- 是 --> F1[折抵不成功<br/>reason = INVALID_POINTS<br/>R-POINTS_REDEMPTION-001]
  C2 -- 否 --> C3{折抵點數 > 點數餘額？}
  C3 -- 是 --> F3[折抵不成功<br/>reason = INSUFFICIENT_POINTS<br/>R-POINTS_REDEMPTION-003]
  C3 -- 否 --> C4{折抵金額 > 折抵上限？<br/>上限 = floor(訂單金額 × 30%)}
  C4 -- 是 --> F2[折抵不成功<br/>reason = EXCEEDS_LIMIT<br/>R-POINTS_REDEMPTION-002]
  C4 -- 否（含等於上限） --> OK([進入：折抵成交與結果回傳])
```

## 白話複述
1. 訂單金額是 0 或負數、或點數餘額是負數、或兩者不是整數 → 整筆拒絕，原因 INVALID_INPUT；最先檢查（R-POINTS_REDEMPTION-004）
2. 折抵點數不是整數（如 10.5）或是負數 → 整筆拒絕，原因 INVALID_POINTS（R-POINTS_REDEMPTION-001）
3. 折抵點數比餘額多 → 整筆拒絕，不自動折到餘額用完，原因 INSUFFICIENT_POINTS；同時超過上限仍報這個（R-POINTS_REDEMPTION-003）
4. 折抵金額超過上限（訂單金額 × 30% 無條件捨去）→ 整筆拒絕，不自動截斷，原因 EXCEEDS_LIMIT；剛好等於上限可以（R-POINTS_REDEMPTION-002）

## 已知取捨
- X-POINTS_REDEMPTION-001：餘額持久化扣款不在本模組
- POLICY-001：超過上限整筆拒絕不截斷；POLICY-002：百分比上限小數無條件捨去
