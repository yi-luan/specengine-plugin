# BENCH-LOG：T3-A-r2 多租戶優惠券

- 開始時間：2026-10-20 07:43:48
- 結束時間：2026-10-20 07:45:38

## 假設（需求未明講，依最佳判斷決定）

1. 任一張傳入的優惠券不合格時，整筆套用是「全部失敗」還是「跳過該券、其餘照用」？→ 決定全部失敗（ok:false）並回傳該券的失敗原因；不做部分套用。
2. 有效期間的起、迄時間點本身是否可用？→ 決定起迄皆含（validFrom <= now <= validTo）。
3. 「不可疊加的優惠券一張訂單只能用一張」是否也禁止與可疊加券同用？→ 決定只要訂單有超過一張券且其中任一張不可疊加即失敗（NOT_STACKABLE）；不可疊加券單獨使用可以。
4. 百分比折扣算出小數時如何取整？→ 決定無條件捨去（Math.floor）到整數元，對商家較保守。
5. 多張百分比券同時使用時，每張是各自以折扣前金額計算再加總，還是逐張遞減計算？→ 依規則 10 決定每張皆以折扣前的原始訂單金額計算，折扣總額為各券折扣加總。
6. 固定金額折扣使訂單金額低於 0 時，是失敗還是把金額截為 0？→ 決定失敗（BELOW_ZERO），折扣剛好等於訂單金額（結果 0）則允許；此下限檢查套用在所有券折扣加總後的最終金額。
7. 最低消費是以折扣前還是折扣後的訂單金額判定？是否含等於？→ 決定以折扣前原始訂單金額判定，且訂單金額等於最低消費即可使用。
8. 同一張優惠券代碼在 coupons 中重複傳入怎麼辦？→ 依規則 11 視為錯誤（DUPLICATE_CODE）整筆失敗；跨租戶同代碼不衝突（會先被租戶檢查擋下）。
9. coupons 為空陣列時？→ 視為成功，finalAmount = orderAmount、discount = 0、applied = []。
10. 失敗原因（reason）的格式？→ 決定為「英文代碼: 繁中說明」（例如 `EXPIRED: 優惠券 PAST 已過期`），說明中帶出問題券的代碼，方便前端判斷與使用者閱讀。
11. 檢查順序（多個問題同時存在時回傳哪個原因）？→ 決定依序：訂單金額 → now 可解析 → 租戶 → 代碼重複 → 券型別/數值 → 有效期間 → 最低消費 → 疊加規則 → 折扣後金額低於 0。
12. 輸入資料本身不合法（orderAmount 非整數或負數、now/validFrom/validTo 無法解析、value 非正整數、PERCENT 超過 100、minOrderAmount 非非負整數、type 非兩者之一）怎麼辦？→ 依規則 12「所有金額以整數元計算」與純函式特性，決定回傳 ok:false 並附對應原因，不丟例外。
13. 折扣後金額的計算是否也對 PERCENT 套用「不得低於 0」？→ 因 PERCENT 限制 1~100，單張不會低於 0；多張加總後仍統一以最終金額 < 0 判定失敗。
