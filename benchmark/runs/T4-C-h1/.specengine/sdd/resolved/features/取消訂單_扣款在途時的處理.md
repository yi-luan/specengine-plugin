# 釐清問題
訂單在「處理中」時，顧客送出取消。但此時庫存服務可能已發出 StockReserved，付款服務尚未扣款（或還沒收到）。需求沒有說明這種競態時付款服務該怎麼做。事件保證至少送達一次但不保證順序，所以這種情況一定會發生。

# 定位
MODULE_ID：EVENT_DRIVEN_ORDER；相關規則 R-EVENT_DRIVEN_ORDER-002、R-EVENT_DRIVEN_ORDER-003。

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 付款服務照常扣款，之後收到 OrderCancelled 時立即全額退款並發出 PaymentRefunded。結果一致，但會產生一次扣款與退款。 |
| B | 付款服務收到 StockReserved 時先檢查訂單是否已取消，若已取消則不扣款、不發任何事件。需要付款服務也追蹤取消狀態。 |
| C | 付款服務照常扣款且不退款，直到顧客另行處理。與取消語意衝突，不建議。 |
| Short | 自訂簡答（<=5 字） |

# 影響範圍
影響 R-002（付款扣款條件）與 R-003（退款觸發條件）；付款服務需要的狀態資料；測試案例需要設計 OrderCancelled 先於 StockReserved 的亂序情境。

# 優先級
High

Yes（任何「非同步補償」流程都會遇到的取消與在途請求競態）
