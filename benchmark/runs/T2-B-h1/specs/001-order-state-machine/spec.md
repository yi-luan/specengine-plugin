# Feature Specification: 訂單狀態機

**Feature Branch**: `001-order-state-machine`

**Created**: 2026-10-31

**Status**: Draft

**Input**: User description: "需求：訂單狀態機（見 requirement.md）"

## Clarifications

### Session 2026-10-31

- Q: 已付款訂單取消時，退還的全部已付金額是否計入「累計退款金額」？ → A: 計入。取消後狀態為「已取消」，refundedAmount = paidAmount（FR-010）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立與付款訂單 (Priority: P1)

營運人員建立一筆訂單，訂單金額必須為大於 0 的整數元。已建立的訂單可以付款，付款金額必須恰好等於訂單金額，付款成功後訂單狀態變為「已付款」。

**Why this priority**: 所有後續流程都以「已建立」與「已付款」為起點，是最小可用的核心價值。

**Independent Test**: 建立一筆金額 1000 元的訂單，付款 1000 元，確認狀態為「已付款」且已付金額為 1000 元。

**Acceptance Scenarios**:

1. **Given** 無任何前置條件, **When** 建立金額為 1000 元的訂單, **Then** 訂單狀態為「已建立」，金額 1000，已付金額 0，累計退款 0。
2. **Given** 建立金額為 0 或負數, **When** 嘗試建立訂單, **Then** 操作失敗並回傳失敗原因，不產生訂單。
3. **Given** 狀態為「已建立」、金額 1000 的訂單, **When** 付款 1000 元, **Then** 狀態變為「已付款」，已付金額為 1000。
4. **Given** 狀態為「已建立」、金額 1000 的訂單, **When** 付款金額為 999 或 1001 元, **Then** 操作失敗並回傳失敗原因，訂單維持「已建立」。
5. **Given** 狀態為「已付款」的訂單, **When** 再次嘗試付款, **Then** 操作失敗並回傳失敗原因。

---

### User Story 2 - 出貨與取消訂單 (Priority: P1)

已付款的訂單可以出貨，出貨後狀態變為「已出貨」。已建立或已付款的訂單可以取消，取消後狀態變為「已取消」；已付款的訂單取消時，系統退還全部已付金額。

**Why this priority**: 出貨與取消是訂單離開主流程的兩條基本路徑，與 User Story 1 合起來構成完整的非退款生命週期。

**Independent Test**: 分別跑出「已付款 → 已出貨」與「已付款 → 已取消（全額退還）」兩條路徑，確認狀態與金額正確。

**Acceptance Scenarios**:

1. **Given** 狀態為「已付款」的訂單, **When** 出貨, **Then** 狀態變為「已出貨」。
2. **Given** 狀態為「已建立」的訂單, **When** 出貨, **Then** 操作失敗並回傳失敗原因。
3. **Given** 狀態為「已建立」的訂單, **When** 取消, **Then** 狀態變為「已取消」。
4. **Given** 狀態為「已付款」、已付金額 1000 的訂單, **When** 取消, **Then** 狀態變為「已取消」，系統退還全部 1000 元。
5. **Given** 狀態為「已出貨」的訂單, **When** 取消, **Then** 操作失敗並回傳失敗原因。
6. **Given** 狀態為「已取消」的訂單, **When** 任何操作, **Then** 操作失敗並回傳失敗原因。

---

### User Story 3 - 分次退款（已出貨訂單）(Priority: P2)

已出貨的訂單可以申請退款。退款可以分多次進行，累計退款金額不得超過已付金額。當累計退款金額達到已付金額時，狀態變為「已退款」。

**Why this priority**: 退款是較少發生的終端流程，依賴前面的付款與出貨，但仍是需求明訂的核心規則。

**Independent Test**: 對一筆已付金額 1000 元、已出貨的訂單分兩次退款（400 元、600 元），確認第一次後仍為「已出貨」、第二次後變為「已退款」。

**Acceptance Scenarios**:

1. **Given** 狀態為「已出貨」、已付金額 1000 的訂單, **When** 退款 400 元, **Then** 累計退款為 400，狀態維持「已出貨」。
2. **Given** 累計退款為 400 的訂單, **When** 再退款 600 元, **Then** 累計退款為 1000，狀態變為「已退款」。
3. **Given** 累計退款為 400、已付金額 1000 的訂單, **When** 退款 601 元, **Then** 操作失敗並回傳失敗原因，累計退款維持 400。
4. **Given** 狀態為「已付款」的訂單, **When** 申請退款, **Then** 操作失敗並回傳失敗原因。
5. **Given** 狀態為「已退款」的訂單, **When** 申請退款, **Then** 操作失敗並回傳失敗原因。

---

### Edge Cases

- 退款金額為 0 或負數時，操作失敗並回傳失敗原因。
- 付款金額為 0 或負數時，操作失敗並回傳失敗原因。
- 「已付款」訂單取消後，狀態為「已取消」，累計退款金額等於已付金額（FR-010）。
- 「已退款」狀態只能由累計退款剛好等於已付金額時達成；不得因超過已付金額而進入此狀態（超額操作直接失敗）。
- 任何失敗操作都 MUST NOT 改變訂單的狀態與金額。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在建立訂單時將狀態設為「已建立」，且訂單金額 MUST 為大於 0 的整數元。金額不符時 MUST 失敗並回傳原因。
- **FR-002**: 系統 MUST 僅允許「已建立」的訂單付款。付款金額 MUST 恰好等於訂單金額；付款成功後狀態 MUST 變為「已付款」，且已付金額 MUST 記錄為該筆付款金額。
- **FR-003**: 系統 MUST 僅允許「已付款」的訂單出貨，出貨成功後狀態 MUST 變為「已出貨」。
- **FR-004**: 系統 MUST 僅允許「已建立」或「已付款」的訂單取消，取消成功後狀態 MUST 變為「已取消」。
- **FR-005**: 已付款的訂單取消時，系統 MUST 退還全部已付金額。
- **FR-006**: 系統 MUST 僅允許「已出貨」的訂單申請退款。退款金額 MUST 為大於 0 的整數元，且可分多次申請。
- **FR-007**: 每次退款成功後，累計退款金額 MUST 增加該次退款金額；累計退款金額 MUST NOT 超過已付金額，超過時 MUST 失敗並回傳原因。
- **FR-008**: 當累計退款金額達到已付金額時，狀態 MUST 變為「已退款」；未達到時狀態 MUST 維持「已出貨」。
- **FR-009**: 每次操作成功時，系統 MUST 回傳更新後的訂單；操作失敗時，系統 MUST 回傳失敗原因，且訂單狀態與金額 MUST 保持不變。
- **FR-010**: 已付款的訂單取消成功時，狀態 MUST 變為「已取消」，且累計退款金額 MUST 設為已付金額（退款全額計入累計退款）。（需求方於 2026-10-31 確認，Q1: A）
- **FR-011**: 所有操作 MUST 為純函式：不得修改傳入的訂單，成功時回傳新的訂單物件。
- **FR-012**: 所有金額 MUST 為整數元。

### Key Entities *(include if feature involves data)*

- **訂單 (Order)**: 代表一筆交易。屬性包含：訂單識別碼、狀態（已建立／已付款／已出貨／已取消／已退款）、訂單金額、已付金額、累計退款金額。
- **訂單狀態**: 五種狀態之一，決定哪些操作可以執行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 需求的 8 條業務規則皆有對應的驗收情境，且全部通過（測試全綠）。
- **SC-002**: 所有不合法的操作（金額不符、狀態不允許、超額退款）都回傳失敗原因，且訂單狀態與金額在失敗前後完全相同。
- **SC-003**: 每次成功操作回傳的訂單，其狀態與金額與上述規則的預期結果一致，無例外。

## Assumptions

- 金額一律為整數元，不考慮小數與貨幣單位。
- 一筆訂單只會有一次完整付款（付款金額等於訂單金額），不支援分期付款。
- 退款只針對「已出貨」訂單；已付款、已取消、已退款的訂單不可申請退款。
- 本功能不處理訂單的持久化、識別碼產生或重複檢查；訂單識別碼由呼叫端提供。
- 本功能不處理退款的實際金流（僅更新訂單資料）。
- 「已退款」僅在累計退款恰好等於已付金額時達成（見 FR-008）。
