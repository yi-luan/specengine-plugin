# 釐清問題
顧客搶購時輸入不合理，系統該怎麼反應？情況：(1) 搶購件數 <= 0 或不是整數；(2) 搶購編號對應的檔次不存在。另外，商品頁查詢「不存在的檔次」的剩餘件數要顯示什麼？

# 定位
R-FLASH_SALE-000、R-FLASH_SALE-015、FlashSale.grab、FlashSale.getRemaining；模組 FLASH_SALE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 搶購件數不合法或檔次不存在一律回傳失敗、不建立保留；查詢不存在檔次的剩餘件數回傳 0。 |
| B | 搶購件數不合法或檔次不存在一律回傳失敗；查詢不存在檔次的剩餘件數時拋出例外（呼叫端自行處理）。 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
grab 的前置驗證、getRemaining 對不存在檔次的回傳、相關測試案例

# 優先級
Medium

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：Short（需求方自填）：「搶購時 qty 不是正整數，或 saleId／customerId／requestId 為空字串 → `INVALID_INPUT`；搶購編號不存在 → `SALE_NOT_FOUND`，都不改任何資料。不存在檔次的剩餘查詢：你決定。」執行者決定（需求方授權）：查詢不存在檔次的剩餘可搶件數回傳 0，不拋例外。
