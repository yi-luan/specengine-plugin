# 釐清問題
同一個搶購請求因網路逾時被重送（請求編號相同），第二次送達時系統該回什麼？需求只說「同一個請求可能被重送」，沒說重送時怎麼回應。

# 定位
R-FLASH_SALE-000、grab_requests.request_id、FlashSale.grab；模組 FLASH_SALE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 冪等回放：第一次若成功，重送回傳同一個保留編號與到期時間（不另建保留、不重複扣件）；第一次若失敗（例如當時剩餘不足），重送時重新評估。對呼叫端最友善。 |
| B | 拒絕重送：第二次回傳失敗，告知為重複請求。呼叫端須自行查詢結果。 |
| C | 完整回放：不論第一次成功或失敗，重送一律回傳第一次的結果。最嚴格的冪等，但第一次失敗後顧客用同一請求編號就永遠搶不到。 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
grab_requests 表、grab 回傳值、重送相關測試案例

# 優先級
High

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：A。需求方補充：「前一次成功：回同一張保留（同 holdId、同到期時間），不重複佔名額、不重算限購。前一次失敗：當成新請求重新判斷。」
