# 釐清問題
顧客搶購時指定的件數比剩餘可搶件數多（例如剩 2 件，顧客要 3 件），系統該怎麼反應？需求只說「絕對不能超賣」，沒有說是整筆拒絕還是只給剩下的件數。

# 定位
R-FLASH_SALE-005（剩餘不足）、FlashSale.grab；模組 FLASH_SALE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 整筆拒絕：回傳失敗，不建立保留，剩餘件數不變。顧客可自行改件數重搶。實作最單純，不會出現「搶到的件數跟我要的不一樣」。 |
| B | 部分成交：只保留剩下的件數（上例保留 2 件），回傳成功。需在回傳中讓顧客知道實際件數，且限購計算也以實際件數為準。 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
flash_sales.remaining、holds.qty、grab 的成功／失敗判定與測試案例（剩餘不足的所有 Scenario）
