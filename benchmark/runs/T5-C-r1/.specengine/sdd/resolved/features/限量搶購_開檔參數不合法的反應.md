# 釐清問題
商家開檔時參數不合理，系統該怎麼反應？可能的情況：限量件數 <= 0、限購件數 <= 0、限購件數大於限量件數、結束時間不晚於開始時間、件數不是整數、時間字串不是合法 ISO 8601。

# 定位
R-FLASH_SALE-001、flash_sales.*、FlashSale.openSale；模組 FLASH_SALE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 上述情況一律拒絕：回傳失敗、不建立檔次。規則最單純。 |
| B | 限購件數大於限量件數時自動截為限量件數並建立成功；其餘情況拒絕。 |
| C | 不檢查：照單全收建立檔次，由商家自行負責。 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
openSale 的前置驗證、flash_sales 欄位約束、開檔參數邊界的 Examples 列

- **決策選項**：Short（需求方自填）：「quantity 或 perCustomerLimit 不是正整數、saleId 為空、開始時間不早於結束時間 → `INVALID_INPUT`，不改任何資料。限購大於限量、時間格式不合法：你決定，照你的最佳判斷。」執行者決定（需求方授權）：限購大於限量【允許】開檔、不拒絕（限購實際受剩餘件數自然限制，記入 exclusions X-FLASH_SALE-003）；開始或結束時間無法解析為合法 ISO 8601 → `INVALID_INPUT`。
