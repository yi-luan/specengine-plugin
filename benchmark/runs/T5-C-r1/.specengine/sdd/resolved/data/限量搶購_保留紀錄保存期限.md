# 釐清問題
保留紀錄（含已成交、已釋放）與請求編號紀錄要保存多久？影響：事後以保留編號查詢能否查到；網路重送隔很久才到時能否辨識為同一請求。

# 定位
holds、grab_requests；模組 FLASH_SALE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 永久保存：保留與請求紀錄不設存活期限，任何時候都查得到。儲存持續成長，需另有清理機制（本模組不做）。 |
| B | 搶購結束後一段時間自動清除：例如結束時間後 24 小時以 px 自動失效。儲存可控，但之後查詢保留會回 null。 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
holds 與 grab_requests 的寫入是否帶 px、getHold 在久遠之後的回傳

# 優先級
Low

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 來源
spec-01

# 最終決策
- **決策選項**：需求方回覆「你決定，照你的最佳判斷」。執行者決定（需求方授權）：A。保留紀錄與請求紀錄永久保存、不設存活期限，任何時候以保留編號查詢都查得到；清理不在本模組。理由：確保已成交／已釋放的保留可被事後查核，且重送辨識不受時間影響。
- **寫回位置**：exclusions X-FLASH_SALE-002（系統無動作：不自動清除保留與請求紀錄）；erm.dbml holds、grab_requests note；policy-defaults POLICY-009
