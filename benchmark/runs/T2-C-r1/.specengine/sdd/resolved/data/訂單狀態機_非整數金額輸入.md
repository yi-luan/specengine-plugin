# 釐清問題
需求說金額皆為整數元，但 TypeScript 的 number 可以傳入小數（例如 10.5）或 NaN。createOrder／pay／refund 收到非整數或非有限數值時，系統該怎麼反應？

# 定位
Order.amount、Order.paidAmount、Order.refundedAmount（orders.amount／paid_amount／refunded_amount）；模組 ORDER_STATE_MACHINE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕，回傳 ok=false 與失敗原因（視同金額不合法） |
| B | 自動取整（捨去小數）後繼續 |
| C | 不檢查，信任呼叫端一定傳整數 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
三個函式的輸入驗證、erm.dbml 的金額欄位 note

# 優先級
Low

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 來源
spec-01

# 最終決策
- **決策選項**：使用者裁示「你決定，照你的最佳判斷」→ 執行者採 A：非整數或非有限數值視同金額不合法，拒絕並回傳 INVALID_AMOUNT（與 POLICY-002、DBML int 型別一致）
