# 釐清問題
折抵點數換算的金額超過訂單金額的 30%（例如訂單 1000 元，想折 301 點）時，系統該怎麼反應？需求寫「不得超過」，但沒有寫超過時是拒絕還是自動修到上限。

# 定位
R-POINTS_REDEMPTION-（新 Rule）；PointsDiscountInput.orderAmount、pointsToUse；MODULE_ID = POINTS_REDEMPTION

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕並回傳失敗原因，不自動截斷（規則清楚、結果可預期） |
| B | 自動截斷到上限（例如折 300 點）並回傳成功（對會員友善，但實際折抵數與輸入不同，呼叫端要自行比對） |
| C | 忽略超出部分、照上限折抵並在結果附警告（需擴充回傳型別，與固定介面衝突） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
applyPointsDiscount 的失敗／成功分支；若選 A，需另定 reason 文案；對應一組 edge_case Scenario（上限值由「30% 取整方式」題決定）。
