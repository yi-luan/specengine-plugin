# 釐清問題
訂單金額或點數餘額本身不是整數（例如訂單 100.5 元、餘額 99.9 點；介面型別為 number，傳得進來）時，系統該怎麼反應？需求寫「金額與點數皆以整數元／整數點計算」，但沒有定義非整數輸入要拒絕還是容錯。使用者於流程圖對齊時裁示「你決定，照你的最佳判斷」，仍需以選擇題落盤決策。

# 定位
R-POINTS_REDEMPTION-007 的 pre_conditions（或新 Rule）；PointsDiscountInput.orderAmount、pointsBalance；MODULE_ID = POINTS_REDEMPTION

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 視為非法輸入，拒絕並回傳 INVALID_INPUT（與 R-007、POLICY-002 一致；非有限數 NaN／Infinity 同樣拒絕） |
| B | 自動取整（無條件捨去）後繼續計算（容錯，但默默改掉呼叫端的數值） |
| C | 不檢查，照原值計算（最簡單，但回傳結果可能帶小數，違反「整數元／整數點」） |
| Short | 自訂簡答 (<=5 字) |
