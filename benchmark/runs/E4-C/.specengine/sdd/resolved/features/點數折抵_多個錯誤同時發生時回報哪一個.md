# 釐清問題
同一次呼叫同時踩到多個錯誤（例如折抵點數既超過餘額、又超過 30% 上限）時，回傳的失敗原因要報哪一個？回傳型別的 reason 只有一個字串。

# 定位
全部 edge_case Rule 的 post_assertions；PointsDiscountResult.reason；MODULE_ID = POINTS_REDEMPTION

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 固定檢查順序，回報第一個命中的（結果可預期；需一併決定順序，例如 輸入合法性 → 點數整數 → 餘額 → 上限） |
| B | 全部錯誤合併成一個字串回報（資訊完整，但文案格式要另定） |
| C | 只報最嚴重的一個（需另定嚴重度排序） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
所有失敗分支的 Scenario 期望值；實作時的驗證順序。

# 優先級
High

Yes
