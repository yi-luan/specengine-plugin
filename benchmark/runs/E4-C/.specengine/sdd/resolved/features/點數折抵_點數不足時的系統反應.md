# 釐清問題
會員想用的折抵點數比他的點數餘額還多（pointsToUse > pointsBalance）時，系統該怎麼反應？需求只說「折抵成功後要扣掉點數」，沒有說餘額不夠時怎麼辦。

# 定位
R-POINTS_REDEMPTION-（新 Rule）；PointsDiscountInput.pointsBalance、pointsToUse；MODULE_ID = POINTS_REDEMPTION

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 整筆拒絕：回傳 ok=false 與失敗原因，不折抵任何點數（規則單純，但會員要自己改數字再試） |
| B | 自動折到餘額用完：以餘額為折抵點數繼續成功（對會員友善，但回傳結果與輸入不一致，需額外告知） |
| C | 拒絕並在失敗原因中附上「最多可用 N 點」的提示（介於 A、B 之間，reason 要帶數值） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
applyPointsDiscount 的失敗分支；若選 A／C，需另定 reason 文案（記入 terms.md 固定文案）；對應一組 edge_case Scenario。
