# 釐清問題
同一動作重複觸發時（例如已付款的訂單再付款一次、已出貨的訂單再出貨一次），系統要怎麼反應？需求沒有寫。

# 定位
Order.status = PAID 時 pay、Order.status = SHIPPED 時 ship；模組 ORDER_STATE_MACHINE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 拒絕，回傳失敗原因（狀態不允許），不視為冪等 |
| B | 視為冪等成功，回傳與傳入相同內容的新訂單物件 |
| C | 再付款拒絕；再出貨冪等成功 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
pay()／ship() 的狀態檢查、對應 Scenario

# 優先級
Low

# 可複用慣例候選 (Reusable Policy Candidate)
Yes

# 最終決策
- **決策選項**：使用者回答「你決定，照你的最佳判斷」，授權執行者裁量；執行者選 A：拒絕，reason 固定 INVALID_TRANSITION，不視為冪等成功（與其他狀態不允許的操作一致）。
