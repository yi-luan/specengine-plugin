# 釐清問題
付款金額是 0 或負數（例如 pay(order, 0)）時，依 POLICY-003（金額 0／負數不合法）與 POLICY-001 的檢查順序（先金額合法性再比對）應回 INVALID_AMOUNT；但 R-ORDER_STATE_MACHINE-003 寫「付款金額不等於訂單金額 → AMOUNT_MISMATCH」也涵蓋 0 與負數。兩者重疊時該回哪個代碼？

# 定位
R-ORDER_STATE_MACHINE-003 的 pre_conditions（pay amount ≤ 0）；模組 ORDER_STATE_MACHINE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 先查金額合法性：付款金額 ≤ 0 回 INVALID_AMOUNT；只有金額 > 0 且不等於訂單金額才回 AMOUNT_MISMATCH（與 POLICY-001 順序一致） |
| B | 付款只做比對：任何不等於訂單金額的付款（含 0 與負數）一律 AMOUNT_MISMATCH |
| C | 0 回 AMOUNT_MISMATCH，負數回 INVALID_AMOUNT |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
pay() 的檢查順序、R-ORDER_STATE_MACHINE-003 pre_conditions、可能新增一條 Rule、Scenario Outline 邊界列
