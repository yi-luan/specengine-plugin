# 釐清問題
需求第 8 點說失敗時回傳失敗原因，但沒說原因長什麼樣。reason 要用固定的代碼（例如 INVALID_AMOUNT）還是白話句子？每一種失敗（建立金額不合法、付款金額不符、狀態不允許操作、退款超過上限）各用什麼文案？另外同一次操作同時踩到多個錯（例如已取消的訂單又用錯誤金額付款）時，先報哪一個？

# 定位
OrderResult.reason；影響 R-ORDER_STATE_MACHINE-001、003、008 與所有拒絕類 Rule；模組 ORDER_STATE_MACHINE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 固定英文代碼（如 INVALID_AMOUNT、AMOUNT_MISMATCH、INVALID_TRANSITION、REFUND_EXCEEDS_PAID），檢查順序先狀態再金額，程式與測試逐字比對 |
| B | 繁體中文白話句子（如「付款金額與訂單金額不符」），檢查順序先狀態再金額 |
| C | 固定代碼，但檢查順序先金額再狀態 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
所有失敗路徑的 Then 文案、terms.md 固定文案、src/order.ts 的 reason 字串與檢查順序

# 最終決策
- **決策選項**：A。固定英文代碼：INVALID_AMOUNT、AMOUNT_MISMATCH、INVALID_TRANSITION、REFUND_EXCEEDS_PAID。檢查順序：先狀態（INVALID_TRANSITION）→ 再金額合法性（INVALID_AMOUNT）→ 再金額比對（AMOUNT_MISMATCH / REFUND_EXCEEDS_PAID）。建立訂單金額不合法 → INVALID_AMOUNT。
- **寫回位置**：terms.md 固定文案 MSG-001～MSG-004；矩陣 R-ORDER_STATE_MACHINE-001（reason=INVALID_AMOUNT）、-003（AMOUNT_MISMATCH）、-008（REFUND_EXCEEDS_PAID）、新增 -010（多重錯誤優先序）；policy-defaults.md POLICY-001
