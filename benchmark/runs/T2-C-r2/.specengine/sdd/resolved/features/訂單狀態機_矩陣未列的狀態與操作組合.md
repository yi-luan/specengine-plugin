# 釐清問題
流程圖對齊時發現矩陣沒有涵蓋兩個狀態×操作組合：已建立（CREATED）訂單申請退款、已出貨（SHIPPED）訂單再付款。這些組合系統要怎麼反應？是否可以概括成「凡未明列為允許的狀態×操作組合，一律拒絕」？

# 定位
Order.status = CREATED 時 refund、Order.status = SHIPPED 時 pay；影響 R-ORDER_STATE_MACHINE-010 的狀態檢查通則；模組 ORDER_STATE_MACHINE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 一律拒絕，reason 固定 INVALID_TRANSITION，並明訂通則：矩陣未明列為允許的狀態×操作組合全部視為狀態不允許 |
| B | 已建立退款拒絕（INVALID_TRANSITION）；已出貨再付款視為冪等成功 |
| C | 兩者都允許：已建立退款視同取消；已出貨再付款視為加購（累加已付） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
refund()／pay() 的狀態檢查、R-ORDER_STATE_MACHINE-010 通則敘述、對應 Scenario

- **決策選項**：使用者回答「你決定，照你的最佳判斷」，授權執行者裁量；執行者選 A：CREATED 退款、SHIPPED 再付款一律拒絕 INVALID_TRANSITION，並明訂通則「未明列為允許的狀態×操作一律拒絕」。
