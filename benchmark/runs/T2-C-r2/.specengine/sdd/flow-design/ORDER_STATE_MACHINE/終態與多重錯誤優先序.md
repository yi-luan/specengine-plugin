# 終態與多重錯誤優先序

已取消、已退款為終態，任何操作一律拒絕；所有操作的檢查順序固定為先狀態、再金額合法性、再金額比對；未明列的狀態×操作組合視為狀態不允許。

- rule_id：R-ORDER_STATE_MACHINE-010, 011, 012, 018

```mermaid
flowchart TD
  T1[已取消 CANCELLED] --> O1([付款／出貨／退款／再取消]) --> O1x[失敗 INVALID_TRANSITION<br/>R-011]
  T2[已退款 REFUNDED] --> O2([退款／出貨／取消／付款]) --> O2x[失敗 INVALID_TRANSITION<br/>R-012]
  M([任一操作]) --> K1{狀態允許？<br/>未明列即不允許 R-018}
  K1 -- 否 --> K1x[INVALID_TRANSITION<br/>R-010 先狀態]
  K1 -- 是 --> K2{金額合法（> 0）？} -- 否 --> K2x[INVALID_AMOUNT]
  K2 -- 是 --> K3{金額比對} -- 不符 --> K3x[AMOUNT_MISMATCH / REFUND_EXCEEDS_PAID]
  K3 -- 相符 --> OK[成功，回傳新訂單物件]
```

白話複述：
1. 已取消後任何操作 → INVALID_TRANSITION（R-011）；已退款後任何操作 → INVALID_TRANSITION（R-012）
2. 狀態不允許且金額同時有錯，只回 INVALID_TRANSITION（R-010）
3. 凡矩陣未明列為允許的狀態×操作 → INVALID_TRANSITION（R-018）
4. 所有操作皆為純函式，不修改傳入訂單
