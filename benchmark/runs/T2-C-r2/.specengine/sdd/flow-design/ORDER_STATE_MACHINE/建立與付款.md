# 建立與付款

客戶建立訂單並付款，直到訂單進入已付款；含金額不合法、金額不符與重複付款的失敗分支。

- rule_id：R-ORDER_STATE_MACHINE-000, 001, 002, 003, 010, 017, 018, 019

```mermaid
flowchart TD
  A([客戶建立訂單 createOrder]) --> B{金額 > 0？}
  B -- 否 --> B1[失敗 INVALID_AMOUNT<br/>R-001]
  B -- 是 --> C[已建立 CREATED<br/>paid 0 / refunded 0<br/>R-000]
  C --> D([客戶付款 pay amount])
  D --> E0{amount ≤ 0？}
  E0 -- 是 --> E0x[失敗 INVALID_AMOUNT<br/>R-019]
  E0 -- 否 --> E{amount = 訂單金額？}
  E -- 否（少付或多付） --> E1[失敗 AMOUNT_MISMATCH<br/>R-003]
  E -- 是 --> F[已付款 PAID<br/>paid = 訂單金額<br/>R-002]
  F --> G([再付款一次]) --> G1[失敗 INVALID_TRANSITION<br/>R-017]
  S[已出貨 SHIPPED] --> H([付款]) --> H1[失敗 INVALID_TRANSITION<br/>R-018 通則]
```

白話複述：
1. 金額 > 0 建立 → 已建立、已付 0、已退 0（R-000）；金額 ≤ 0 → INVALID_AMOUNT（R-001）
2. 已建立付款：金額 ≤ 0 → INVALID_AMOUNT（R-019）；金額 > 0 但不等 → AMOUNT_MISMATCH（R-003）；相等 → 已付款（R-002）
3. 已付款再付款 → INVALID_TRANSITION（R-017）；已出貨付款 → INVALID_TRANSITION（R-018）
4. 狀態不允許且金額也錯時只回 INVALID_TRANSITION（R-010，沿用）
