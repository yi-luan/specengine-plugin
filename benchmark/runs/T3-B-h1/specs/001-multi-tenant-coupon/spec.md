# Feature Specification: 多租戶優惠券

**Feature Branch**: `001-multi-tenant-coupon`

**Created**: 2026-10-31

**Status**: Draft

**Input**: User description: "需求檔 tasks/t3/requirement.md（多租戶優惠券）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 單張優惠券結帳套用 (Priority: P1)

結帳時，某租戶的顧客提交一張優惠券代碼與訂單金額，系統判斷該券是否可用於此訂單；可用時回傳折扣後金額、折扣總額與實際套用的優惠券代碼，不可用時回傳失敗原因。

**Why this priority**: 這是優惠券功能的最小可交付價值，沒有它其他故事都無從成立。

**Independent Test**: 以單一租戶、單張有效優惠券與一筆訂單金額執行結帳，確認折扣後金額、折扣總額與套用代碼正確；並以單張失效優惠券執行，確認回傳失敗原因。

**Acceptance Scenarios**:

1. **Given** 租戶 A 有一張有效期間內、百分比 10% 的優惠券，**When** 對租戶 A 的 1000 元訂單套用該券，**Then** 折扣總額為 100 元，折扣後金額為 900 元，實際套用代碼為該券代碼。
2. **Given** 租戶 A 有一張固定金額 300 元的優惠券，**When** 對租戶 A 的 1000 元訂單套用，**Then** 折扣總額為 300 元，折扣後金額為 700 元。
3. **Given** 一張優惠券的有效期間為 2026-01-01 至 2026-06-30，**When** 在 2026-07-01 套用，**Then** 套用失敗並回傳失敗原因。
4. **Given** 一張優惠券的最低消費為 500 元，**When** 對 400 元的訂單套用，**Then** 套用失敗並回傳失敗原因。
5. **Given** 一張屬於租戶 A 的優惠券，**When** 以租戶 B 的訂單套用，**Then** 套用失敗並回傳失敗原因（優惠券只能用在同一租戶的訂單）。

---

### User Story 2 - 多張優惠券合併計算 (Priority: P2)

顧客可以在同一筆訂單同時套用多張優惠券。可疊加的優惠券可以多張同時使用；不可疊加的優惠券一張訂單只能用一張。

**Why this priority**: 多券疊加是常見的促銷組合，但建立在 P1 的單券規則之上。

**Independent Test**: 以兩張可疊加券與一張不可疊加券的組合分別執行，確認可疊加券都被套用、不可疊加券的數量限制被遵守。

**Acceptance Scenarios**:

1. **Given** 兩張可疊加券（10% 與固定 100 元），**When** 對 1000 元訂單同時套用，**Then** 兩張都被套用，百分比折扣以折扣前金額 1000 元計算為 100 元，折扣總額為 200 元，折扣後金額為 800 元。
2. **Given** 兩張不可疊加券，**When** 同時套用於同一訂單，**Then** 整筆套用失敗並回傳失敗原因（一張訂單只能用一張不可疊加券）。
3. **Given** 一張固定金額 800 元的可疊加券與一張固定金額 500 元的可疊加券，**When** 對 1000 元訂單同時套用，**Then** 折扣後金額不得低於 0，折扣總額不超過 1000 元，折扣後金額為 0。
4. **Given** 多張優惠券，**When** 套用成功，**Then** `applied` 依傳入順序列出實際套用的優惠券代碼。

---

### User Story 3 - 固定金額與金額規則 (Priority: P3)

所有金額以整數元計算；固定金額折扣不得使訂單金額低於 0；同一租戶內優惠券代碼唯一。

**Why this priority**: 屬於資料與金額正確性的保護規則，重要但可在 P1、P2 之後補強。

**Independent Test**: 以固定金額大於訂單金額的情境與整數金額情境分別執行，確認結果符合規則。

**Acceptance Scenarios**:

1. **Given** 一張固定金額 1500 元的優惠券，**When** 對 1000 元訂單套用，**Then** 折扣後金額為 0，折扣總額為 1000 元。
2. **Given** 任何套用成功的結果，**When** 檢視金額，**Then** 折扣總額、折扣後金額皆為整數元。

---

### Edge Cases

- 沒有提交任何優惠券時，結果應為無折扣（折扣後金額等於訂單金額，折扣總額為 0，套用代碼為空）。
- 優惠券的有效期間起訖時刻等於傳入的 `now` 時，視為有效（起迄皆包含）。
- 最低消費恰等於訂單金額時可用（未達才拒絕）。
- 券本身的值不合法（PERCENT 不在 1–100、FIXED 小於等於 0、非整數）時，整筆拒絕，原因為 `INVALID_COUPON`。
- 同一張券（同 tenantId 與 code）在同一次請求中被傳入兩次，整筆拒絕，原因為 `DUPLICATE_COUPON`。
- 提交的多張券中部分有效、部分失敗時，整筆拒絕（見 FR-013）。
- 提交的代碼在該租戶中不存在時，失敗原因為 `COUPON_NOT_FOUND`。此判定屬於呼叫端查券流程；`applyCoupons` 接收的是已取得的券物件，不會回傳此代碼（見 Clarifications Q6）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓每張優惠券隸屬於單一租戶，且只能用在同一租戶的訂單。
- **FR-002**: 系統 MUST 支援兩種優惠券類型：百分比折扣（PERCENT）與固定金額折扣（FIXED）。
- **FR-003**: 系統 MUST 只允許優惠券在其有效期間（起、迄）內使用。
- **FR-004**: 系統 MUST 支援「可疊加」與「不可疊加」標記；不可疊加的優惠券只能單獨使用。若一筆結帳請求中包含不可疊加券與任何其他券（含兩張以上不可疊加券），整筆拒絕，失敗原因為 `NOT_STACKABLE`。
- **FR-005**: 系統 MUST 允許多張可疊加的優惠券同時套用於同一訂單。
- **FR-006**: 固定金額折扣 MUST NOT 使訂單金額低於 0。
- **FR-007**: 優惠券 MAY 設定最低消費金額；訂單金額未達最低消費者 MUST NOT 使用該券。
- **FR-008**: 結帳成功時，系統 MUST 回傳折扣後金額、折扣總額與實際套用的優惠券代碼（依傳入順序）。
- **FR-009**: 套用失敗時，系統 MUST 回傳失敗原因代碼，且只使用下列固定代碼：
  - `TENANT_MISMATCH`：優惠券不屬於訂單所屬租戶。
  - `COUPON_EXPIRED`：優惠券已過期或尚未生效（兩者使用同一代碼）。
  - `MIN_ORDER_NOT_MET`：訂單金額未達優惠券最低消費。
  - `NOT_STACKABLE`：不可疊加券與其他券同時提交（含兩張以上不可疊加券）。
  - `COUPON_NOT_FOUND`：提交的代碼在該租戶中不存在。
  - `INVALID_COUPON`：券本身的值不合法（PERCENT 不在 1–100、FIXED ≤ 0、非整數）。
  - `DUPLICATE_COUPON`：同一張券（同 tenantId + code）在同一次請求中出現兩次。
- **FR-010**: 百分比折扣 MUST 一律以折扣前的訂單金額計算。
- **FR-011**: 同一租戶內優惠券代碼 MUST 唯一。
- **FR-012**: 所有金額 MUST 以整數元計算。
- **FR-013**: 多張券提交時，任一張失敗即整筆拒絕，不套用任何券；回傳的原因為第一張失敗券（依傳入順序）的原因代碼。

### Key Entities

- **優惠券 (Coupon)**: 屬於某租戶，具有代碼、類型（百分比或固定金額）、折扣值、有效期間、可疊加標記，以及選填的最低消費金額。
- **結帳請求 (Apply Request)**: 包含租戶、訂單金額、提交的優惠券清單與當下時間。
- **結帳結果 (Apply Result)**: 成功時包含折扣後金額、折扣總額與套用代碼清單；失敗時包含失敗原因。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對每一項規則（FR-001 至 FR-012），至少有一個可自動執行的情境能驗證其成立與不成立兩側。
- **SC-002**: 所有成功結帳的結果中，折扣後金額皆不低於 0，且折扣總額加折扣後金額等於訂單金額。
- **SC-003**: 所有失敗結帳的結果都包含非空的失敗原因。

## Assumptions

- 最低消費以折扣前的訂單金額比較。
- 有效期間以時間戳比較：`validFrom ≤ now ≤ validTo`（起迄皆包含）。
- 不屬於該租戶的優惠券視為不可用，並回傳失敗原因。
- 同一租戶內代碼唯一性為資料層約束；本功能的套用邏輯不負責建立或維護優惠券資料。
- 需求檔指定的公開介面名稱與資料形狀（`Coupon`、`ApplyInput`、`ApplyResult`、`applyCoupons`）為固定約束，不可更名。
- 本功能本身不讀寫資料庫，所有判斷只依傳入的資料與時間。

## Clarifications

### Session 2026-10-31

- Q1 不可疊加券與其他券的關係：整筆拒絕，不可疊加券只能單獨使用；兩張以上不可疊加券一起用也整筆拒絕。失敗原因 `NOT_STACKABLE`。
- Q2 多券部分失敗：整筆拒絕。跨租戶 `TENANT_MISMATCH`；過期或尚未生效 `COUPON_EXPIRED`；未達最低消費 `MIN_ORDER_NOT_MET`。代碼不存在由規格補定為 `COUPON_NOT_FOUND`（需求方授權由我判斷）。
- Q6 `COUPON_NOT_FOUND` 的觸發點：由需求方授權決定，固定介面不可更改，因此由呼叫端查券流程回傳，`applyCoupons` 不回傳此代碼。
- Q3 券值合法性：PERCENT 不在 1–100、FIXED ≤ 0、非整數，整筆拒絕，原因 `INVALID_COUPON`。
- Q4 重複提交：同一張券（同 tenantId + code）在同一次請求中傳兩次，整筆拒絕，原因 `DUPLICATE_COUPON`。
- Q5 期間邊界：起迄皆包含，以 `validFrom ≤ now ≤ validTo` 判定。
