# 釐清問題
需求第 8 點說事件可能亂序送達。訂單已經到了最終狀態（已確認／庫存不足／付款失敗／已取消）之後，才收到另一個會改變狀態的事件，例如：訂單已被逾時取消或顧客取消後，才收到遲來的 PaymentSucceeded；或已確認後才收到 PaymentFailed。訂單服務該怎麼處理？

# 定位
R-ORDER_SERVICE-001、R-ORDER_SERVICE-002、R-ORDER_SERVICE-003（狀態事件）、orders.status；模組 ORDER_SERVICE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 最終狀態不可逆：忽略遲來的事件，狀態與取消原因不變，handle 回傳空陣列（退款由付款服務收到 OrderCancelled 時自行處理） |
| B | 以最後收到的事件為準：狀態被覆寫（例如已取消 → 已確認），不發事件 |
| C | 忽略並補救：狀態不變；但「已取消」的訂單再收到 PaymentSucceeded 時，額外再發一次 OrderCancelled 以確保付款服務退款 |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
R-ORDER_SERVICE-001／002／003 的前置條件（只在「處理中」生效或任何狀態皆生效）；handle 的亂序測試案例
