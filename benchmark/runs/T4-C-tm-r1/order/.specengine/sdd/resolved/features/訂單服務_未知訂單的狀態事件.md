# 釐清問題
訂單服務收到 PaymentSucceeded、StockRejected 或 PaymentFailed，但事件裡的訂單編號是本服務從未建立過的訂單（例如整合測試時直接灌入事件）。訂單服務該怎麼處理？

# 定位
R-ORDER_SERVICE-001、R-ORDER_SERVICE-002、R-ORDER_SERVICE-003（狀態事件）、orders.order_id；模組 ORDER_SERVICE

# 多選題選項
| 選項 | 描述 (工程 Trade-off) |
|---|---|
| A | 忽略：不建立訂單、不改任何狀態，handle 回傳空陣列；之後查詢該訂單編號仍回傳 undefined |
| B | 拋出例外中止 handle（讓整合端察覺事件來源有問題） |
| Short | 自訂簡答 (<=5 字) |

# 影響範圍
handle 對未知訂單編號的分支；R-ORDER_SERVICE-001／002／003 的前置條件

# 優先級
Low

# 可複用慣例候選 (Reusable Policy Candidate)
No

spec-01

# 最終決策
- **決策選項**：使用者回覆「你決定，照你的最佳判斷」，授權執行者裁量；執行者依最佳判斷採 A — 忽略：不建立訂單、不改狀態、回空陣列，查詢仍為 undefined（理由：與 POLICY-002「亂序事件一律忽略、不拋錯」一致，且 handle 介面不以例外表達錯誤）
